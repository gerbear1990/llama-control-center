# LCC Audit — Refactor, Optimization, and Feature Opportunities (2026-07-14)

Produced at the end of the shell-code-removal pass (see
`docs/superpowers/specs/2026-07-14-shell-code-removal-design.md`). Line counts
were measured after that removal landed. Priorities: **High** = clear payoff,
do next; **Medium** = worthwhile when touching the area; **Low** = nice-to-have.

## 1. Refactors

- **[High] Split `lcc_api/static/app.js` (3,816 lines) into ES modules.**
  One file currently holds the API client, global `state`, every panel
  renderer, modals, the command palette, keyboard handling, and utilities.
  Suggested split: `api.js` (fetch wrappers), `state.js`, `panels/`
  (`profiles.js`, `servers.js`, `models.js`, `parameters.js`, `hardware.js`,
  `chat.js`), `modals.js`, `palette.js`, `util.js`, with `index.html` loading
  `type="module"`. The pure helpers already extracted for tests
  (`formatServerMetricsLine`, `buildPortableExportSnapshot`,
  `COMMAND_REGISTRY`) show the codebase is ready for this. Biggest single
  win for future editability.
- **[High] Split `lcc_api/static/styles.css` (4,105 lines).** At minimum:
  design tokens/theme variables, base layout, and per-panel sheets
  (`@import` under one entry file or `<link>`s). Pair with the app.js split
  so panel code and panel styles move together.
- **[Medium] Extract FastAPI routers from `lcc_api/app.py` (680 lines).**
  Natural seams already visible: profiles (`/api/profiles*`), servers
  (`/api/servers*`), models/HF (`/api/models/*`, `/api/hf-cli*`,
  `/api/draft-models/*`), system (`/api/system*`, `/api/meta`, `/health`),
  estimates (`/api/estimate/*`, `/api/benchmarks*`). Move request models
  alongside their router.
- **[Medium] `lcc_core/server_manager.py` (1,128 lines).** Mixes tracked-state
  persistence, process/port detection, launch orchestration, WSL/vLLM stop
  logic, and the crash watchdog. Suggested split: `server_state.py`
  (state file read/write/trim), `process_utils.py` (pid/port checks, already
  partially psutil-based), keeping `server_manager.py` as the orchestration
  layer. The vLLM-in-WSL specifics (launch + `wsl.exe` stop script) could
  join `vllm_args.py` in a `vllm_wsl.py`.
- **[Low] `lcc_core/estimates.py` (998) and `hardware.py` (994).** Both are
  cohesive but dense. estimates: the quant/bpw pricing tables could move to a
  data module; hardware: per-OS probes (CIM / system_profiler / lspci) could
  split by platform. Only worth doing when next touching them.

## 2. Optimizations

- **[Medium] Double model scan in `profile_registry.register_discovered_models`.**
  `resolve_profiles()` internally calls `discover_models()`, then the registry
  calls `discover_models()` again — two directory walks + GGUF stats per scan
  (startup and `POST /api/profiles/scan`). Inherited from the old
  `generate_all_launch_scripts`. Fix: let `resolve_profiles` (or a variant)
  return the discovered models it already computed.
- **[Medium] `/api/profiles` recomputes everything per call.** Each request
  re-runs manifest load + directory scan + GGUF metadata + fit enrichment.
  The GGUF meta cache keyed on (size, mtime) softens this, but a short TTL
  cache (the `/api/system/live` 2s lock+TTL pattern already in the codebase)
  on the resolved-profiles payload would make dashboard refreshes snappier.
- **[Low] `AppConfig.load()` reads config.json from disk in nearly every
  endpoint.** Cheap but repeated; a mtime-checked cached loader would remove
  the noise.
- **[Low] Startup autoscan blocks the ASGI lifespan.** The registration scan
  runs synchronously before the server accepts requests; with large model
  folders this delays first paint. Could run as a background task after
  startup instead.

## 3. Feature wins (cross-referenced with ROADMAP.md)

- **Backend shipped, UI missing — cheapest high value** (all three have
  working endpoints today, per ROADMAP "Running Server Tooling"):
  - Crash-watchdog surfacing: badge crashed servers (+ `oom_likely`), show
    last stderr lines, offer restart. Detection shipped v0.13.1.
  - Live server metrics panel: `GET /api/servers/{id}/metrics` already
    returns KV usage, slots, decode t/s, RSS, GPU bytes; the servers panel
    renders only a single line of it.
  - Log tail panel: `GET /api/servers/{id}/logs` exists; add a tailing view
    so bad launches are debuggable in-app.
- **New since this pass:** surface `POST /api/profiles/scan` as a
  "Rescan models" button (Settings or Models panel). Registration currently
  runs only at app startup, so a model dropped in mid-session isn't
  registered until restart.
- **Quant picker** (ROADMAP "Quant Selection"): repo file listing (already
  fetched for the HF update check) × `fit.py` verdict per quant.
- **Ollama integration** and **OpenCode provider auto-sync** — both already
  scoped in ROADMAP; larger efforts.

## 4. Repo / process

- `REVIEW_MILESTONES.md` predates this pass; its counts and remaining-work
  lists are now partially stale (launch-script items are gone).
- Test suite: 152 tests, ~37s locally; the API smoke tests dominate. Fine for
  now; consider `-p no:cacheprovider` in CI or splitting slow/live tests if
  it grows.
- `index.html` carries a manual cache-buster (`?v=0.15.0`) that must be
  bumped by hand each release; deriving it from `lcc_api.__version__` at
  template-serve time would remove a recurring chore.
- The branch name `codex/smart-fit-kv-cache-tuning` no longer matches its
  contents (vLLM/NVFP4 + this removal pass); worth merging/renaming when it
  lands.
