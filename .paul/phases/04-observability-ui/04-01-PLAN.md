<objective>
## Goal
The dashboard stops going quiet once a server is running. The metrics payload gets a
panel instead of one text line, logs can be followed rather than snapshotted, and a
model dropped in mid-session can be registered without restarting the app.

## Purpose
LCC is strong pre-launch (discover → fit → estimate → start) and thin afterwards. Every
endpoint needed to close that loop already ships and is tested; the data simply isn't on
screen. This is the cheapest high-value work in the codebase for exactly that reason.

## Output
- A live metrics panel for the selected server
- A log tail that follows, with stdout and stderr distinguishable
- A global "Rescan models" control
- Node tests for the new pure helpers, **wired into the pytest driver**
</objective>

<prior_findings>
**Phase 4 is smaller than `docs/2026-07-14-audit.md` says.** The audit lists all three
observability features as "backend shipped, UI missing". Verified against the tree on
2026-08-21, after the terminal-instrument pass merged in `83f957b` — that pass already
built a good deal of this, leaving comments referencing `M2.1`/`M2.2`/`M1.3`:

| Audit item | Actual status |
|---|---|
| Crash-watchdog surfacing (M2.2) | **Done.** `buildServerItemHtml` renders a `crashed` badge, an `OOM` badge from `oom_likely`, a 300-char `last_stderr` snippet, and a Restart button |
| Metrics polling | **Done.** The tracked-server poll already fetches `/metrics` for running/crashed/startup_timeout servers |
| Live metrics panel (M2.1/M2.3) | **Partial.** The payload is rendered by `formatServerMetricsLine()` into a *single line* on the server card, used in exactly one place. `health`, `props`, `cpu_percent` and the raw `metrics` map are fetched and thrown away |
| Log tail (M2.4) | **Partial.** `loadLogs()` pulls 160 lines once and dumps `stderr + stdout` concatenated into `showLogPreview()`, which sets `textContent` and stops. No follow, no refresh, no separation |
| "Rescan models" button | **Missing.** The only `/api/profiles/scan` call is the per-model row Register action added in `cb1818f`. `#portability-rescan` rebuilds inventory/portability, which is a different thing |

So: do not rebuild crash surfacing, and do not touch the polling loop — extend what
renders. The remaining work is presentation plus one missing control.

**Reuse the existing polling idiom.** The live-hardware widget already polls on an
interval and pauses when the tab is hidden or the panel is collapsed. The log tail must
follow that same pattern rather than introducing a second one.

**Do not restyle.** The terminal-instrument system landed in `83f957b` and `DESIGN.md` is
the schema of record: monospace for machine data, 1px hairlines, accent left edge via the
shared `--rail` token. New panels adopt it; they do not extend or reinterpret it. The
parked Obsidian Rail overhaul stays out of scope.
</prior_findings>

<acceptance_criteria>

## AC-1: Metrics panel shows what the payload carries
```gherkin
Given a running server with a metrics payload
When its card is selected
Then a panel shows KV-cache usage, slots, prompt and decode tokens/sec,
     context length, process RSS, GPU bytes, CPU percent, and health
  And a field the payload omits is absent rather than rendered as null or NaN
```

## AC-2: The log tail follows
```gherkin
Given the log panel is open for a server with follow enabled
When the server writes new output
Then the panel updates without user action
  And stdout and stderr are distinguishable
  And polling stops while the browser tab is hidden
```

## AC-3: A model dropped in mid-session can be registered
```gherkin
Given a new model file appears in a scan root after app start
When the operator activates "Rescan models"
Then POST /api/profiles/scan runs with no model_path
  And the number of newly registered profiles is reported
  And the profiles list refreshes
```

## AC-4: New pure helpers are actually covered
```gherkin
Given a node test exists for a new formatter
When the pytest suite runs
Then that node test executes as part of it
```
