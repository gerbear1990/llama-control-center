<objective>
## Goal
`app.js` stops being a 5,222-line file that only its author can navigate. Code moves into
ES modules loaded natively by the browser — no build step, no bundler, no dependencies —
and the node tests stop regex-slicing source text and start importing real exports.

## Purpose
Every future phase pays a tax on this file. It is the largest single obstacle to the
remaining milestone work (M2.5 running-state indicators, M3.2 concurrency hygiene, M3.4
parameters editor, M3.6 table enhancements all live inside it). The split is worth doing
for its own sake, but it is worth doing *now* because Phase 1's restyle has landed and
Phase 4 wired up the test cover it needs to be safe.

## Output
- `lcc_api/static/js/` holding leaf utilities, shared systems, and one module per panel
- `app.js` reduced to an entry point: import, wire, boot
- Six node tests importing real exports instead of scraping text
- A suite that still reads 258 passed, 2 skipped, 16 subtests
</objective>

<prior_findings>

Verified against the tree on 2026-08-22, not taken from `docs/2026-07-14-audit.md` — which
is stale on this phase in three separate ways.

**The ROADMAP's line counts are wrong.** It says `app.js` is 3,816 lines and `styles.css`
4,105, quoting the audit. Actual: **5,222** and **4,227**. The audit predates the
terminal-instrument pass and the ground-truth layer.

**Every node test scrapes the file it tests.** This is the load-bearing finding and it is
in no planning document:

| Test | Reads | Mechanism |
|---|---|---|
| `test_empty_copy.js` | `app.js` | `indexOf('function profilesEmptyCopy')` → slice → `vm.runInContext` |
| `test_launch_lock.js` | `app.js` | brace-counting `extractFunctionSource(name)` → `vm` |
| `test_metrics_rows.js` | `app.js` | `match(/function buildServerMetricsRows[\s\S]*?\n}/)` → `eval` |
| `test_models_pane_matcher.js` | `app.js` | `indexOf` → slice to next `\nfunction ` → `vm` |
| `test_server_metrics_formatter.js` | `app.js` | same family |
| `test_smart_fit_ui.js` | `app.js` | same family |
| `test_css_shell.js` | `styles.css`, `index.html` | regex over CSS rules — **unaffected by this plan** |

Six of seven break the moment a function moves to another file. They are also silently
weak today: a scrape that finds nothing can only be caught by an explicit guard, and not
all of them guard. Converting them to imports makes a rename fail loudly.

**The usual killer is absent.** `grep` finds **zero** inline `onclick=`/`onchange=`
handlers in `index.html`, **zero** `onclick=` in HTML generated by `app.js`, and **zero**
`window.foo = ...` assignments. All wiring is `addEventListener`. Module scoping therefore
cannot silently break event handling — the single most common way this refactor goes wrong
does not apply here.

**Shared mutable state is small and already clustered.** 21 top-level `let` bindings, and
they group by feature almost perfectly: palette (2), popup menu (5), tools menu (2), port
check (2), polling timers (3), live-hardware history (3), refresh guards (2), log follow (1),
model options cache (1). Only `refreshInFlight`/`refreshGeneration` and `renderedModelOptions`
are genuinely cross-cutting.

⚠️ **ES module bindings are live but read-only across a module boundary.** `import { x }`
gives a live view that the importer **cannot assign to**. Any state read by one module and
written by another must move behind a setter in its owning module, or into `state.js`. This
is the one mechanical trap that will produce a runtime `TypeError` rather than a clean
failure, and it applies to exactly the cross-cutting bindings named above.

**The cache-buster is a non-issue, and can be simplified.** `index.html` carries
`?v=0.16.17` against `__version__ = "0.16.0"` — hand-bumped, already incoherent, and it
cannot propagate to modules imported by relative path anyway. `app.mount("/static",
StaticFiles(...))` sends `etag` + `last-modified`, so browsers revalidate correctly on
their own. Drop the query string rather than inventing a scheme to spread it across N files.

**No build step exists and none is being added.** `PROJECT.md` treats "no build step" as a
property of the product, not an accident. Native `<script type="module">` keeps that true.

</prior_findings>

<boundaries>

## DO NOT CHANGE
- `styles.css` — the CSS split is 05-02, and its cascade-order hazard needs its own plan
- Any backend file. This is a pure frontend reorganisation with **zero** behaviour change
- Test assertions — T2 changes how tests load code, never what they assert
- `test_css_shell.js` — it reads CSS and HTML, neither of which moves here
- The design system. No styling changes ride along with a refactor

## SCOPE LIMITS
- No build step, bundler, transpiler, or new dependency — native ESM only
- No TypeScript, no JSDoc type annotation pass
- No behaviour improvements, however tempting. A refactor that also fixes bugs cannot be
  verified by "everything works the same"
- Not fixing M3.2 (abort controllers / sequence tokens). It pairs with this phase and will
  be far easier afterwards, but mixing it in destroys the no-behaviour-change property
- Not renaming functions. Moving and renaming in one pass makes the diff unreadable

</boundaries>
