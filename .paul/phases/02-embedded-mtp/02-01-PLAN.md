<objective>
## Goal
An embedded-MTP model (Qwen3.5/3.6/3.8, MTP head inside the GGUF) resolves as launchable
and starts from the dashboard, without a `draft_model` and without renaming the profile.
Closes the remaining half of issue #14.

## Purpose
Discovery was fixed in `cb1818f`, so these models are now found — and then immediately
blocked at resolve. Right now the product finds a model it refuses to launch, which is
worse than not finding it. The core value is "see whether a model fits, then run it";
this is the half that doesn't run.

## Output
- `profile_resolver.py` decides MTP from the model file, not the profile's name
- Regression cover pinning the discovery fix that just landed
- Launch flags correct for draft-model-free speculation (pending T2's finding)
</objective>

<prior_findings>
**Most of the original T7 is already built — do not re-implement it.** The paused plan
(`docs/superpowers/plans/2026-07-14-models-pane-and-fixes.md`) predates the ground-truth
layer merged in `a1a6444`. Verified against the tree on 2026-08-21:

| Original T7/T8 item | Actual status |
|---|---|
| Bump gguf-meta cache to v4 | Already 4 — `estimates.py` `_KV_META_CACHE_VERSION` |
| Add `context_length` to the meta tuple | Already there — `_store_meta_cache(...)` |
| Scan `reader.tensors` for nextn/mtp | Already done — `truth/gguf.py` matches `"nextn" in name or ".mtp." in name`, plus `{arch}.nextn_predict_layers` metadata |
| `model_has_builtin_mtp` accessor | Exists as `ArchFacts.has_mtp` — and is **consumed by nothing outside its own tests** |
| Registry skips MTP models | Fixed in `cb1818f` (`_is_draft_model`), but **untested** — hence T1 |
| `spec_type` isn't a profile param | Wrong. It is: `llama_args.py` emits `--spec-type`, validated against `SPEC_TYPES`, and only when there is no `draft_model` |

**The real gap is wiring, not detection.** `profile_resolver.py` decides MTP from
`" ".join([profile.mode, profile.name, profile.description]).lower()` and then demands a
`draft_model` — blocking the exact draft-model-free path `llama_args.py` already supports.

**Cost is a non-issue.** `truth/gguf.read_facts()` is memoized in-process *and* cached on
disk keyed on `(size, mtime)`, added specifically because a cold header read measured
~5.5s. Calling it from the resolver is cheap after the first read. Do not build a second
cache.
</prior_findings>

<acceptance_criteria>

## AC-1: Embedded-MTP model resolves as launchable
```gherkin
Given a profile whose model file contains MTP tensors (ArchFacts.has_mtp is true)
  And the profile has no draft_model set
When the profile is resolved
Then draft_model is absent from the missing list
  And the profile is launchable
```

## AC-2: A genuine missing draft model is still an error
```gherkin
Given a profile whose model file has no MTP tensors
  And the profile text mentions MTP
  And no draft_model is set
When the profile is resolved
Then draft_model appears in the missing list
```

## AC-3: Product names containing MTP are not treated as companions
```gherkin
Given a model file named "Qwen3.8-27B-NVFP4-MTP-Q8attn.gguf"
When the registry scans for launchable profiles
Then that file is registered as a standalone profile
  And a file named "mtp-draft.gguf" or one under an "mtp/" directory is not
```

## AC-4: Unreadable model files degrade, never crash
```gherkin
Given a profile whose model file cannot be read as GGUF
When the profile is resolved
Then resolution completes with the pre-existing text-based behaviour
  And a warning explains that the fact could not be read
```
